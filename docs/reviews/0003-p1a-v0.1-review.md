# Review 0003: P1a V0.1 Readiness

Independent review requested after adding P1a smoke validation and quickstart.

## Review Summary

Overall assessment:

```text
P1a smoke passed on two samples, but the pass result masked grounding risks.
The prototype is aligned with Understanding-Agent direction, but V0.1 should
not call heuristic ordering "dataflow" or treat class/docstring evidence as
confirmed semantic understanding.
```

Recommended priority:

```text
Fix before V0.1:
- conservative claim confidence
- implementation order versus dataflow wording
- visualization edge semantics
- explicit uncertainty for inferred flow and unknown valid propagation
```

## High-Risk Findings

### Dataflow Was Not Actually Grounded

Issue:

```text
P1a created flow edges by zipping selected symbols. The edge evidence pointed
to endpoint class definitions, not producer/consumer data movement.
```

Why it matters:

```text
The artifact looked evidence-grounded while the relation was convention-based.
This risks turning fpga_devmind into a report generator with evidence-looking
claims rather than a grounded Understanding Agent.
```

Suggested change:

```text
Do not call heuristic edges dataflow. Either ground them from step/process body
analysis or mark them as inferred implementation order with uncertainty.
```

### Confirmed Claims Were Too Easy

Issue:

```text
Confirmed implementation claims could be backed by whole class/function spans
derived mostly from names or docstrings.
```

Why it matters:

```text
Names and comments are useful evidence, but should not by themselves confirm
implementation semantics.
```

Suggested change:

```text
Downgrade class/docstring-backed implementation identity to supported unless
claim-type-specific evidence rules are met.
```

### Visualization Could Pass While Semantically Wrong

Issue:

```text
Visualization diagnostics checked only for claim/evidence ids, not whether the
edge evidence proves the edge relation.
```

Suggested change:

```text
Use conservative edge labels and confidence until relation evidence exists.
```

## Medium Risks

```text
- Generic concept inference remains heuristic and token-family based.
- Fixed-point and interface specs are shallow and partly config-driven.
- Pipeline timing must not imply valid propagation when latency/valid movement is unknown.
- Freshness only tracks files read by the extractor.
- Tests still need negative synthetic fixtures for unsupported relationships.
```

## Recommendations

Before V0.1:

```text
- Replace heuristic dataflow claims with inferred implementation_order_claim.
- Downgrade class-backed implementation claims from confirmed to supported.
- Add explicit uncertainty for inferred order versus real dataflow.
- Remove hardcoded target device unless grounded.
- Keep LLM/ReAct, RTL mapping, verification coverage and symbolic totals for later phases.
```
